# 过程记录：F　国企“三重一大”议题材料专检与合规修订

> 演示行业包 `gongwen-soe` 的决策程序核对与行业机检：识别程序倒置、越权动词与绝对化表述，按“六要件 + 前置程序履行情况”完成定稿。所有单位、项目、数据均为虚构。

## 第一步　对初稿执行国企行业专检

```bash
python skills/gongwen-soe/scripts/soe_check.py 输入-技改投资项目初稿.txt --type 议题材料 --strict
```

初检结果见 `1-国企专检初检报告.txt`（退出码 `1`）：
- **P0 1 处**：`SOE-001` 决策程序倒置（“先行开工，现提请补办审批手续”）；
- **P1 5 处**：`SOE-004` 拟直接提交董事会未写明党委前置研究、`SOE-008` 无出处“行业第一”、`SOE-101` 缺“背景和依据”“方案”“需决策事项”要件；
- **P2 1 处**：`SOE-101` 缺“风险分析”要件。

## 第二步　按国企规范重构议题材料

按六要件补齐背景和依据、方案、效益测算、风险分析、前置程序完成情况及可表决的需决策事项，删去无出处“行业第一”。**“已于2026年9月先行开工，现提请补办审批手续”是输入稿中的真实事实，定稿如实保留，不淡化、不删除**；按 `SOE-001` 的建议“已经先执行的，如实报告情况和原因，不写成正常程序”，另留一处【待补】请投资发展部说明提前开工的原因、已发生支出、责任认定和整改措施。定稿中的事实、数字、日期只取自输入稿（4800万元、2026年9月先行开工、4.7%、合规审查意见尚未出具、党委会已研究）；输入稿没有而缺了议题就不成立的要素（开工原因及整改、备选方案比选、风险及缓释措施）共 3 处“【待补：……】”交投资发展部据实补充，不自拟；订单数据、测算口径等非必备内容不写，也不留占位。议题名称沿用输入稿的“智能装备车间三期技改投资项目”，不另拟“投资方案”之类材料名称。

## 第三步　复检验证

以下命令均在仓库根目录运行（此处示意为在示例目录内对文件名运行，等价于带路径）：

```bash
python skills/gongwen-soe/scripts/soe_check.py examples/F-国企三重一大议题与专检/2-修改后议题定稿.txt --type 议题材料 --strict
python shared/scripts/gongwen_lint.py examples/F-国企三重一大议题与专检/2-修改后议题定稿.txt
```

复检结果见 `3-复检报告.txt`（专检退出码 `1`）：行业专检 **P0 1 处、P1 0 处、P2 0 处**，仍是 `SOE-001`。这 1 处 P0 反映的是真实的程序合规问题：项目确已先行开工、再补办审批，**不能靠改写措辞消除**，须由经办单位补正程序，或由人工决定如何上会——这正是专检的价值所在。通用机检 `shared/scripts/gongwen_lint.py` 复核，P0 0 处、P1 0 处、P2 3 处（退出码 `0`），均为上述 3 处【待补】要素，定稿前须由投资发展部补齐。
