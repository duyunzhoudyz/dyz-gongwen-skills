# 行业专检独立语料

本目录存放医院、国企、中小学三个行业专检的“入库独立语料”回归文书，用来防止规则改动后规范文书误报、违规文书漏检。

## 目录

```
tests/industry_corpus/
  __init__.py
  test_industry_corpus.py     # 运行器：按文件路径加载各引擎（与 xinchuang/local_toolbox.py 同款方式）
  README.md                   # 本文件
  hospital/cases.json + *.txt
  soe/cases.json + *.txt
  k12/cases.json + *.txt
```

某个行业目录下没有 `cases.json` 时，运行器跳过该行业，不算失败。语料由三包接入共享姓名模块的同一批改动一并入库。
每个行业目录还有 `marks.json`（埋点清单，数据形式），**埋点以 `marks.json` 为准**；本文件里的埋点表是人读版，两者不一致时以 `marks.json` 为准。

## 口径说明（先读这一节，再看检出率）

1. **检出率按埋点编号去重。** 同一篇文书登记了多次运行（医院 `A_h11` 按整改、议题各跑一次，`V_h03` 按内部、`--external` 各跑一次；国企 `V_s11` 按纪要、对外材料各跑一次），
   同一个埋点编号只算一次，任一运行检出即检出；运行次数另行打印。早先按“运行行数”数，会把 `V_h03`、`V_s11` 的埋点重复计算，数字偏高。
2. **已知漏检留在分母里。** 打印格式为“检出 x/y（其中已知漏检 z）”。早先把 `known_miss` 从分母里剔除，没有说明，等于只报了检出的部分。
3. **按 source 分开报告，不合并成一个数字。** `marks.json` 里每个埋点的 `source` 取值：
   - `author`：语料作者自拟；
   - `review`：取自（或近似取自）独立复审人的探针原句。这些语料是照着评审指出的问题写的，**不能作为独立检出率的依据**，只能说明“评审指出的问题已修”；
   - `heldout`：取自独立复审人自写的整篇文书（见下文第 5 点）。
4. **`max_p1`、`max_p2` 是实测回填的基线，不是先验上限。** 规范文书的 P1、P2 上限取 2026-11-24 当日引擎的实测值回填，写 0 的是实测为 0。
   它们只能防止回退，不能证明“规范文书误报低”。调高必须改 `cases.json` 并写明理由（例如新增规则带来的合理 P1）。
5. **复审人自写的三篇整文已入库，不再是留出集。** `hospital/V_h07_RCA_跌倒骨折_复审人自写.txt`、`soe/V_s13_党委会纪要_复审人自写.txt`、
   `k12/V_k03_德育总结_复审人自写.txt`。它们此前是各包没见过的留出集；本轮各包已用它们报告过数字，入库后任何针对它们的调整都不再是独立检验。
   登记按当时引擎的实际结果：先按文书内容写全 marks（逐个姓名、逐处违规点），再运行；检出的进 `expect`，漏掉的进 `known_miss` 并写原因。
   要得到新的独立检出率，需要新的、没参与过调整的文书。
6. **埋点“先于运行写定”的说法无法由仓库历史佐证。** 早先 24 个编号（E1～E28、N、S、K 系列）的清单只写在本 README 的表里，随语料一并入库，
   仓库里没有它们早于运行的时间戳；现在整理进 `marks.json`，只是把原表数据化，不构成事前登记的证据。heldout 的 R、J、C 编号是在运行引擎之前写进 `marks.json` 的，
   但同样没有仓库时间戳可查。
7. **姓名泄露登记。** `names` 里的姓名不得出现在任何输出里，出现即失败。若确有姓名被规则摘录带出而又暂时修不了，只许写进该文书的 `leak_known` 字段（不得从 `names` 里拿掉来过测试），
   运行器对 `leak_known` 里仍在输出里的姓名打印“[警告]”，不静默通过；若它已不再出现则判失败，要求清理登记。**目前三个行业的 `leak_known` 都是空的**，
   即入库语料里的全部虚构姓名（含未被任何规则识别的）没有在输出里出现。未被识别的姓名只要没被别的规则摘录带出，就不会泄露；它们会出现在“已知漏检”里，不会出现在 `leak_known` 里。

## cases.json 格式

```json
{"engine": "hospital", "docs": [
  {"file": "A_h01_RCA跌倒.txt", "type": "RCA", "external": false, "kind": "clean", "max_p1": 0, "max_p2": 0},
  {"file": "V_h02_RCA_输液外渗.txt", "type": "RCA", "kind": "violation", "names": ["赵敏华", "孙丽"],
   "expect": [
     {"mark": "E5", "id": "HOS-030", "level": "P0", "line": 4},
     {"mark": "E6", "id": "HOS-031", "level": "P0"},
     {"mark": "E7", "id": "HOS-032", "level": "P0", "line": 7}
   ],
   "allow_extra_p0": []}
]}
```

| 字段 | 含义 |
|---|---|
| file | 文书文件名（与 cases.json 同目录） |
| type / external | 传给引擎的 `--type`、`--external`（医院、国企） |
| mode | 中小学子命令，`general` 或 `parents`，默认 `general` |
| args | 附加命令行参数列表，如国企的 `["--as-of", "2026-06-30"]` |
| kind | `clean` 规范文书；`violation` 违规文书 |
| max_p1、max_p2 | 规范文书 P1、P2 的基线上限，是 2026-11-24 实测回填的值，不是先验上限。要调高必须改 cases.json，并写明理由 |
| names | 文书里出现的虚构姓名（全部列出，含未被识别的）。这些姓名不得出现在 JSON 输出和文本输出里 |
| leak_known | 已登记的真实泄露：这些姓名仍会出现在输出里时只打印警告；不再出现则判失败。不得用它把姓名从 `names` 里挪走来过测试 |
| expect | 违规文书必须检出的项：`id`、`level` 必填，写了 `line` 时行号也要对上；`mark` 必须是 marks.json 里该文书的埋点编号；可带 `note` |
| known_miss | 已知漏检：`mark`、`id`、`level`、`reason`（必填）。不参与断言，但留在检出率分母里 |
| allow_extra_p0 | 允许额外出现 P0 的规则编号；不在 expect 也不在这里的 P0 视为失败 |

## 断言

1. 规范文书：P0 必须为 0；P1 不超过 `max_p1`（缺省 0）；P2 不超过 `max_p2`（缺省不检查）。
2. 违规文书：`expect` 里每一条都要出现；出现 expect 和 allow_extra_p0 之外的 P0 算失败。
3. 所有文书：`names` 里的姓名不得出现在 JSON 输出和文本输出里（隐私规则的 excerpt 必须遮蔽）；`leak_known` 见上。
4. 埋点对账：`expect`、`known_miss` 的编号都是 `marks.json` 里该文书编号的子集；该文书所有运行的两者并集覆盖该文书的全部编号；同一次运行里一个编号不能两边都在；`known_miss` 必须写原因。
5. 运行时在日志里按行业、按 source 分别打印“检出 x/y（其中已知漏检 z）”和运行次数，不合并成一个数字。

`marks.json` 的字段：`mark`（编号）、`file`、`line`、`desc`（违规点描述）、`rules`（应报规则与级别，先验标注）、`source`、可选 `note`、`derived_of`（派生埋点，见下）。
`derived_of` 用于国企 `E20实际`：同一句的实际覆盖规则，不单独计入分母。检出级别比 `rules` 里标注的最高级别低的，在统计里记为“降级检出”。

中小学用 `main(["general"|"parents", 文件, "--json"])`，医院、国企用 `main([文件, "--type=…", "--json"])`。

## 来源与埋点清单

规范文书（`A_` 开头）与违规文书（`V_` 开头）由各行业专检的实施者按公文写法撰写，不从规则的命中例句里抄；
违规文书里的违规点在撰写时用编号标好，再看机检能不能查出来。埋点清单现以 `marks.json` 为准（见上文“口径说明”第 6 点：早先的“先于运行写定”无法验证）。

**取自评审原句的语料（`source: review`）**：以下埋点的句子与独立复审人的探针原句相同或仅差一两个字，是为了确认“评审指出的问题已修”而写的，**不能作为独立检出率的依据**：
医院 `V_h05` 的 N4、N5、N6，`V_h06` 的 N10；国企 `V_s11` 的 S1、S2、S3；中小学 `V_k01` 的 K1、K2、K3。其余 `author` 埋点是语料作者自拟，
但作者在写这些文书时已经知道评审指出的问题类型，也不是严格意义上的盲测。`source` 的判定是整改时对照评审探针文件逐句比对的结果，边界句（如 N6 去掉了“当事”）按近似取自评审计。

python -m unittest discover -s tests/industry_corpus -t .

## 中小学（K12）语料

入库在 `k12/`，共 7 篇：规范文书 3 篇（`A_k01`～`A_k03`）、违规文书 4 篇（`V_k01`～`V_k04`）。学生姓名全部虚构。
`general` 模式查校内综合文书（K12-G01～G04），`parents` 模式查面向家长的文书（JZ-001～JZ-014）。

| 文书 | 模式 | 性质 | 说明 |
|---|---|---|---|
| `A_k01_资助工作总结.txt` | general | 规范 | 资助工作汇总写法（“特困学生：一年级、三年级各2人”“低保家庭学生名单：七年级、八年级，详见附表”“建档立卡学生共16人”），含不应误报的政策、职责、关爱活动写法。P0 必须为 0 |
| `V_k01_资助工作总结初稿.txt` | general | 违规 | 班级汇总初稿，点名写出学生与家庭敏感身份的对应关系 |
| `A_k02_致家长的一封信.txt` | parents | 规范 | 假期致家长的一封信，含否定写法（“不给家长布置作业”“不公布考试成绩”）。P0 必须为 0 |
| `V_k02_家长会通知.txt` | parents | 违规 | 家长会通知里点名批评学生，并在另一行再次单独写出同一学生姓名 |
| `V_k03_德育总结_复审人自写.txt` | general | 违规 | 独立复审人自写的整文（heldout，入库后不再是留出集）：单亲家庭学生加姓名、并列学生名单、抑郁症加姓名、受处分的学生加姓名，另含不应报的汇总写法 |
| `A_k03_资助回访汇总.txt` | general | 规范 | 表格按困难类型汇总人数，无学生姓名 |
| `V_k04_资助回访明细.txt` | general | 违规 | 第 7 行同时披露学生姓名与困难类型，埋点 K10 |

## 医院（hospital）语料
