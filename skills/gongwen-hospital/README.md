# 公立医院行业包（gongwen-hospital）

> 版本 1.1.0　成熟度：Stable（稳定版）

给医院职能部门和临床科室主任用的专用文书助手。它先把你给的数据和记录整理成一份指标台账，再按模板搭结构、分段成稿。指标名称和口径跟国家文件一致，数值只用你给的，必须由你提供的缺了标【待补】；患者和不良事件当事医务人员的信息会脱敏。

## 能做什么

| 文书 | 说明 |
|---|---|
| 等级评审自评报告 | 按《三级医院评审标准（2025年版）》和本省细则，写前置要求自查、监测指标自评、数据质量核查和整改 |
| 绩效考核（绩效监测）自评分析 | 数据上报前的自评材料，或收到反馈后的结果分析：短板指标、失分原因、改进措施表 |
| 医疗质量分析报告 | 月度、季度、年度质量分析，先给结论，问题、原因、措施一一对应 |
| 不良事件根因分析（RCA） | 时间线、直接原因、促成因素、根本原因，改进措施标强弱；不写处分，不归咎个人 |
| PDCA 案例 | 质量改进项目的成果材料，前后同口径对比，目标达成率写算式 |
| 科室主任述职 | 分清科室成绩和本人作用，DRG、CMI 写明口径；现场述职的口头稿按时长（约 200 字/分钟）一并给出 |
| 党委会议、院长办公会议议题 | 方案比较、前置程序核对、可以直接表决的决定事项 |
| 医德医风和行风建设材料 | 九项准则落实情况自查、行风建设情况报告、医德考评方案和结果报告 |
| 院感与安全检查整改 | 整改方案、整改台账（可转 Excel）、整改情况报告，状态与台账一致，没有佐证的不算完成 |

也可以审这 8 类文书的成稿，比如“帮我看看质控科交上来的国考分析初稿”，它给一页纸摘要和行业问题清单，不重写全文；八关全面核稿用 gongwen-review。

## 可以这样说

1. “二季度质量分析报告月底要上质管会，数据表我贴给你，帮我写一下。”
2. “病区有个病人夜里自己把胃管拔了，护理部让我们做 RCA，上报单和谈话记录都在这。”
3. “国考结果下来了，四级手术和 CMI 都掉了，院长让写个分析，看看问题在哪。”
4. “我是呼吸科主任，明年1月要述职，科室数据有了，帮我搭个架子。”
5. “区卫健委安全检查提了6个问题，帮我出整改台账和整改报告。”

## 输入

- 必需：你手头的材料。数据表、上报单、访谈记录、检查反馈原文、科室报上来的情况都可以，不用先整理。
- 最好说明：写给谁（卫健委、质管会、院长办公会议、党委会议、考核组）、统计周期、依据版本（本省评审细则、当年绩效手册、本院议事规则）。没说的按默认处理，并在起草说明里写明。
- 交付节奏：第一轮就给提纲和正文，缺本省细则的按默认结构成稿，缺的关键数据标【待补】，要问的问题（最多 3 个）放在回复最后，不用等你确认再写。只有四种情况先给框架：述职、个人医德自评缺本人事例；只有题目、没有任何事实和数据；你明确要先看提纲；材料涉密（不处理）。指定了字数或时长而材料撑不起的，用工作性表述补足常规板块、不新增事实，起草说明说明哪几部分是常规表述。
- 可选：单位画像 `.gongwen/单位画像.md`、本院公文处理办法、往年同类材料。

## 输出

在 Claude Code、Codex、Cursor 等能写文件的工具里，输出到 `公文/<日期>-<标题>/`：

| 文件 | 内容 |
|---|---|
| `正文.txt` | 纯文本正文（只含正文），可直接粘进 Word 或交给 gongwen-format 排版 |
| `素材台账.md` | 指标台账：每个数的统计周期、口径、来源系统和状态 |
| `提纲.md` | 提纲 |
| `整改台账.md`、`整改台账.xlsx` | 整改类材料的台账，有 Python 时自动转 Excel |

起草说明只在对话中给出。在网页大模型里使用提示词版时，依次输出正文、起草说明，台账放在起草说明之后。

## 注意事项

1. **保密**：涉密材料请勿输入联网 AI；材料出现敏感信号（个人敏感信息、“内部”“不公开”字样、未公开的人事财务数据）时才在起草说明末尾提示一句。标有“内部资料”“不得外传”的纪检通报、医疗纠纷材料会暂停处理。患者姓名、病案号、住院号、床号，以及当事医务人员的姓名、工号，请先删去；没删的会在稿中改成“患者张某”“当班护士甲”。
2. **不编数据**：指标值、排名、等级、标准值只用你提供的。系统生成的指标（国家监测指标、CMI、DRG 组数、满意度）不会替你计算。卫健绩效评价口径和医保结算口径分开写。已做的措施只用你给的；拟采取的措施按常规写，不替你定日期，更多改进思路放在起草说明里供你取舍。
3. **有些结论必须由你确认**：评审“前置要求”是否发生、述职中本人做了什么、RCA 的事件经过，你没提供的，它只给框架和填写指引，不会替你写。
4. **不做的事**：不为提高指标建议调整病案首页编码；不在 RCA 报告中写处分；不写保证疗效、“国内领先”之类没有依据的话。
5. **机检**：有 Python 环境时，会运行通用机检 `scripts/gongwen_lint.py` 和行业机检 `scripts/hospital_check.py`（查疗效表述、党政联席会议决策、CMI 和百分点写法、不规范的指标名称、已废止的依据、RCA 归咎个人，以及患者隐私、当事人信息、编码与医保、程序倒置、廉洁表述、评审结论、敏感事项等）；实名识别（HOS-030～032）用“锚点 + 候选打分”：先找“患者”“12床”“当班护士”“投诉人”这类带得出姓名的上下文，再在旁边取候选并打分，高置信报 P0、低置信报 P1，报告里姓名一律用〔姓名1〕〔姓名2〕遮蔽（同一个姓名全文编号一致，含没有锚点的行）；“、”并列的后项（“赵立新（主治医师）、钱敏（住院医师）”）即使自身分数不足也会登记并遮蔽，宁可多遮。姓名右侧不再一票否决：标点、身份括注、时间词、亲属词、功能字（在、与、对、因、被等）都算证据，右侧是词表外的普通汉字时看名字用字和姓氏形态，三字名报 P1，两字名不报。识别是启发式检查，没有锚点的姓名（如单独一句“据张丽丽回忆”）识别不了；两字名在“患者、医师、护士”这类弱锚点后接普通动词（“患者张伟病情加重”）不报；名字里带软字（和、会、年、日、时等）或地名机构字、与常用词整词同形（刘海、林海、高峰）又没有强证据的姓名会漏报，少见姓只给 P1；报告文件名里的姓名只有正文也识别到时才遮蔽；机检未识别出的姓名不会被遮蔽，定稿前须人工通读。各类语境下的召回率不写单一百分比，见 tests/names 与 tests/hospital 的测试输出；姓名识别和分句豁免的数据与代码是随包安装的共享模块（scripts/gw_names.py、gw_names.json、gw_clause.py），缺失或损坏时机检直接报错退出，不会显示成“未发现问题”；没有 Python 时按人工清单检查，并在起草说明中注明。
6. **依据会更新**：评审标准、绩效手册、纠风工作要点每年或每几年调整。本包的依据核验于 2026 年 10 月，写材料时以你提供的当年文件为准。

整改情况报告、九项准则自查报告这类“报告”由本包直接成文，不用再转 gongwen-draft。

能调用其他 skill 的工具里会直接调用；对应的核心 skill 没装或在网页版时，会给你交接卡、“新开对话粘贴 `dist/prompts/<skill 名>.md` 继续”的说明和安装命令（见 `references/_shared/style/output-format.md` 第四部分）。

一份季度质量分析的完整链路：gongwen-data 合并科室数据 → gongwen-hospital 建台账、成稿 → gongwen-review 核稿 → gongwen-format 出 docx。

## 成熟度

Stable。8 类专用文书的模板、指标台账、行业机检和评测用例已完成（见 `evals/`）。v1.0 真实模型评测（Sonnet 5.5，16 条用例）中，A 组（装 skill）期望通过率 100.0%（135/135）。v1.1 抽样评测（2026-11-04，A 组 5 例）期望通过率 91.7%（33/36），经复核编造 0 次；触发评测正例 10/10、反例 10/10（沿用 v1.0，本轮 description 与 trigger.json 未改）。按 CONTRIBUTING 的 Stable 标准评定，一线测试反馈在升级后持续收集，确认出现严重问题（编造、红线错误）时降回 Beta。评测记录见仓库根目录 evals/results/v1.1-industry-sample.md，v1.0 记录见仓库根目录 evals/results/v1.0-benchmark.md。已知局限：
- 各省评审实施细则、当年绩效手册的逐项公式、各院议事规则差异大，本包不内置，需要你提供原文；
- 行业机检只覆盖能写成规则的问题，数据是否属实、程序是否履行仍需人工核对；
- 行业机检的实名识别是“锚点 + 候选打分”的启发式检查：高置信报 P0、低置信报 P1，报告用〔姓名N〕显示，各语境的召回见 tests/names 与 tests/hospital 的测试输出，定稿前仍须人工通读。带姓名列的 Markdown 表格默认报 P1，同表有诊断、床号等敏感列时报 P0，公开署名及无个人敏感列的整改分工跳过。分工表另列诊断时照报责任人。应检查的姓名格含未识别残段时，即使同格已有姓名，该行也报一条 P1“姓名列内容未能识别，请人工核对”。两个字以上的汉字残段整段遮蔽，长段还遮蔽以姓氏开头的两字、三字后缀，可能多遮单位或部门用语。识别不了或可能漏报的情形：没有锚点的裸姓名（“据张丽丽回忆”）；无姓名类表头或非 Markdown 表格中的姓名；“患者家属 + 姓名”（“患者家属王淑芬”）；两字名在弱锚点（患者、医师、护士）后接普通动词；含软字（和、会、年、日、时、芷、之）的名字（王和平、马会芳；名字含向、从、以、于的三字名如宋向东、赵从军在强锚点下可识别）；与常用词同形的姓名（刘海、林海、黎明、高峰，无强证据时）；文件名里有而正文没识别到的姓名遮不住。并列链（“、”或“和、与、及、同、跟”连接）里只要有一项被识别，其余姓氏开头的 2～4 字项（含与常用词同形的、复姓的）一律登记并遮蔽，同一锚点下的并列姓名合并成一条；姓名表覆盖全部隐私规则，不分文书类型（是否报出仍按文书类型）；整条链上没有任何一项被识别、无锚点的同形名仍漏报。遮蔽是整串替换并带“并列尾巴”处理，可能多遮（姓名“高明”会把“高明的做法”也遮掉，“单亲”“杜鹃花”可能被遮成〔姓名N〕）；
- 程序倒置（HOS-034）：“已执行 + 提请审议”的组合判定（同句、相邻两句、或只写“于X月开工”）一律只给 P1 提示，按原因给不同文案；P0 只来自显式写法的正则（“先行开工”“先行采购”“事后补办手续”“先……后报批”等），单独的“追认”写法报 P1（HOS-035）；如实声明降级只看同句与紧邻的前、后一句：有未被否定、且是对本事项直接断言的肯定式声明（“属于程序倒置”“未履行决策程序”）而追认、补办的检查范围（声明所在句及其后两句、倒置句及其前后一句）里没有追认、补办，显式命中才由 P0 降为 P1；“如实报告”“如实说明”不算声明，疑问（是否属于）、条件（如属于）、转述（有人认为……的说法）、指他（其他单位）、难以认定、谈不上等写法不算声明，也没有全文级降级；“是不是同一事项”只按字面包含判断，被动、跨段、跨三句以上的写法识别不了，不保证穷尽换说法；
- 豁免（已整改、予以否决、经鉴定等）只看词面，不理解语义：处置类只在命中所在分句内生效，出处类在命中所在分句与紧邻前一分句内生效，**否决、整改、出处写在后一分句的句子会被报出**（“该技术国内领先，经省科技厅鉴定。”报 HOS-003 P1，对外宣传按 P0 降为 P1；改成“经省科技厅鉴定，该技术国内领先”不报）：后续分句里有针对该做法的处置、出处词时 P0 降为 P1 并提示，请人工确认并忽略；后续词同样要过语境检查（“避免违规”“此前已有科室整改”“其他医院也违规”“鉴定意见待出具”“正在申请鉴定”都不算）；同分句里的处置词必须针对被命中的做法（“建议各科室整改到位后调整编码……”“……并已纠正部分漏填编码”不放过）；“经自我评价”“经院内评审”“经本院认定”“初步评价”不算出处；拿不准的会多报而不是漏报；
- 编码红线（HOS-033）只认“为指标调整编码”的写法，“目的在前”的写法（“为提升病例组合指数，建议……填写为主要诊断”）不报，须人工核对；
- 中医医院的评审和绩效监测只给了依据名称，中医特色指标未单独适配。
