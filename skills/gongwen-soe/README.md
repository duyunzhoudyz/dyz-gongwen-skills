# 国有企业行业包（gongwen-soe）

> 版本 1.1.0　成熟度：Stable（稳定版）

帮国有企业董事会办公室、总经理办公室、党群、财务、投资、改革、合规部门的同事写国企特有的文书。它先帮你理清这件事走哪条决策链（党委前置研究、董事会、经理层、职代会），再按模板起草；票数、数据、进展只用你给的记录，须你提供的缺了标【待补】，不替你编。

## 能做什么

| 文书 | 说明 |
|---|---|
| “三重一大”议题材料 | 判定事项类别和是否属于前置研究清单，写方案比选、风险、前置程序完成情况表和需决策事项；党委会版和董事会议案版可以一次出 |
| 董事会议案与决议 | 议案写明决策程序履行情况和逐项可表决的提请审议事项；决议按记录写，并核对出席人数、票数之和、同意票是否过半数、关联董事回避 |
| 总经理办公会纪要 | 只记议定事项，分清同意、原则同意、暂缓；核对是否超出董事会授权；可同时出督办清单 |
| 经营分析报告 | 先建指标台账，再写月度、季度分析；比率用百分点，同比写明基期，原因只写材料里有的 |
| 改革任务台账与进展报告 | 按五种状态口径更新台账，已完成要有佐证，过期未完成标“滞后”；进展报告与台账逐项一致 |
| ESG 和社会责任报告 | 判断是否属于强制披露，搭框架，写“关于本报告”的披露口径，第一轮就交框架和第一章（或你指定的章节），其余章节接着写；删去没有依据的“碳中和”“零事故”“行业第一” |
| 党建与经营融合经验材料 | 每条做法对应到具体项目和结果数据，避免“两张皮”；提法只用你提供的原文 |
| 合规管理报告 | 年度报告、专项报告、重大合规风险事件报告；结论写统计依据，个人信息脱敏 |

## 可以这样说

1. “集团要给子公司增资两个亿，下周上党委会，帮我弄个三重一大的上会材料。”
2. “董事会开完了，记录发你，出个决议，票数帮我核一下。”
3. “昨天总经理办公会的录音转成文字了，出个纪要，督办事项列个表。”
4. “这是9月的财务快报，帮我写份经营分析，乙公司亏损的原因你看看怎么写。”（原因材料里没有的，会标【待补】并告诉你该问什么）
5. “我们是深证100样本股，今年的可持续发展报告怎么搭框架？”

## 输入

- 必需：你手头的材料。会议记录或转写稿、财务快报、可研摘要、上级方案、各部门报来的进展、工作情况，不用先整理。
- 最好提供：本企业的前置研究讨论事项清单、“三重一大”实施办法、董事会授权清单、公司章程中的议事规则。没有的按通用规则判断，并在起草说明里写明。
- 可选：单位画像 `.gongwen/单位画像.md`（单位类型写“国有企业”）、领导偏好卡、往年同类材料。

## 输出

在 Claude Code、Codex、Cursor 等能写文件的工具里，输出到 `公文/<日期>-<标题>/`：

| 文件 | 内容 |
|---|---|
| `正文.txt` | 纯文本正文，可直接粘进 Word 或交给 gongwen-format 排版；两个版本的分别存为 `正文-党委会版.txt`、`正文-董事会议案.txt` |
| `素材台账.md` | 每条事实、数据的内容、来源和状态 |
| `督办清单.md`、`改革任务台账.md` | 按需输出，装有 openpyxl 时可转成 Excel |

起草说明只在对话中给出（最多 5 行，不另存文件）。在网页大模型里使用提示词版时，依次输出正文、起草说明；路线还有下一站的，最后给出交接卡。

## 注意事项

1. **保密**：涉密材料请勿输入联网 AI；只有材料出现个人敏感信息、“内部”“不公开”字样或未公开的人事、财务数据时，才在起草说明末尾提示一句。标注“商业秘密”“内部资料”“不得外传”的材料会停止处理；投标报价、未公开财务数据、并购信息请先确认允许在当前模型中处理；职工名单、身份证号会提醒你脱敏。
2. **程序不倒置**：先开工后上会、“投产后再提交职代会”、拆成几笔规避大额标准的，不会照写，会列进“程序风险提示”并给出按正常顺序推进的写法。纪要不替会议改结论：会上已经定了、但可能超出董事会授权或需要先上党委会的事项，照原意记，在起草说明里提示，请会议主持人确认后再改。
3. **不编造**：票数、出席人数、指标值、改革进展、ESG 数据、党建成效只用你提供的。缺的标【待补】，存疑的写进起草说明请你核实。
4. **对外材料从严**：ESG 报告和对外交流材料会删去未公开信息和没有出处的“领先”“第一”；上市公司的对外数据请董事会办公室确认已披露。决议公告、定期报告不在本包范围内。
5. **事实和判断由你负责**：它帮你搭结构、守程序、查错漏，是否上会、怎么决策由你和你的单位决定。
6. **机检**：有 Python 环境时会运行 `scripts/gongwen_lint.py` 和本包的 `scripts/soe_check.py`（决策程序、拆分规避集体决策、程序倒置组合判定、表决票数、议题要件、台账状态、ESG 披露口径、对外表述、商业秘密标注、个人信息、职工权益程序、状态升级，共 29 条正则规则 + 11 项函数检查）；没有运行时按人工清单自检，并在起草说明中注明。机检是启发式检查，可能误报或漏报，结果须人工复核。
   - **实名识别**（处分对象、敏感人员名单）：先找锚点（“给予……处分”“被开除党籍”“拟提拔人选名单：”），再在锚点旁取候选，按“锚点 + 边界 + 形态”打分；高置信报 P0，低置信（如“宁静”这类歧义姓的两字名）降为 P1，不分内外。处分框架允许“给予/对 + 单位 + 原/时任 + 职务 + 姓名”（如“给予财务部原副部长〔姓名〕党内严重警告处分”“对物资公司副总经理〔姓名〕给予记过处分”，括号内姓名实际会被遮蔽）。处分对象可以用“、”并列并带“分别”（“对相关责任人〔姓名〕、〔姓名〕分别给予……”）；并列链（“、”或“和、与、及、同、跟”连接）里只要有一项被识别，其余姓氏开头的 2～4 字项（含与常用词同形的、复姓的）一律登记并遮蔽，首项没识别而后项识别时回溯登记首项，宁可多遮。没有锚点的单独一句（如“马建国分管的项目……”）识别不了，只有同一姓名在别处被锚点识别过，才靠全文姓名表遮蔽。
   - **遮蔽**：报告里所有规则（含函数检查）的摘录和上下文、文本和 JSON 输出，一律把已识别的姓名写成〔姓名1〕〔姓名2〕，按全文首次出现编号，同一姓名编号相同；“张某”这类代称不遮。完全相同的摘录合并成一条并写明共几处。缺少共享模块 `gw_names.py`、`gw_clause.py` 或姓名数据文件时，脚本直接报错退出（退出码 2），不会假装“没查出来”。
   - **程序倒置**：除“先行开工”等显式写法外，还会判断“已执行”与“提请审议”是否同句或相邻两句出现，**组合判定只在议题材料、议案、纪要、决议中生效**（SOE-001 的正则规则本身不限文书类型）。“已执行”除“已开工建设、已签约”外，还认“已与……签订合同”“已完成……采购、安装”“已进场施工、已开始施工”“主体工程已完成30%”这类常见换说法；不带“已”的“于9月开工”也只报 P1。**组合判定一律只给 P1 提示**（同句、相邻两句、不带“已”的写法、提请对象疑似另一事项如二期或续签、有声明，按原因给不同文案），不报 P0；“已签订的框架协议”这类已执行成分作定语的、提请对象是验收结算备案、收费标准、管理办法、计划预算等事后正常事项的不判。**P0 只来自显式写法的正则**：“先行开工”“先行签约”“事后补办手续”“先……后报批”“边施工边报批”等（SOE-001 的动词里没有“采购”，“设备已先行采购”不报）；单独的“追认”写法由 SOE-002 报 P1。如实声明降级只看同句与紧邻的前、后一句：有未被否定、且是对本事项直接断言的肯定式声明（“属于程序倒置”“未履行决策程序”“该做法违反……规定”），且追认、补办的检查范围（声明所在句及其后两句、倒置句及其前后一句）里没有追认、补办，显式命中才由 P0 降为 P1；被“杜绝、防止、严禁、不属于、自查”等否定的不算声明，疑问（是否属于）、条件（如属于）、转述（有人认为……的说法）、指他（其他单位）、难以认定、谈不上等写法也不算，“如实报告”“如实说明”单独出现同样不算，没有全文级降级。常见换说法会被识别，但机检按固定搭配判断，**不保证穷尽所有换说法，须人工复核**。
   - **豁免范围**：处置类（否决、整改、违规）只在命中所在分句内生效，出处类在命中所在分句与紧邻前一分句内生效，**否决、整改、出处写在后一分句的句子会被报出**：后续分句里有针对该做法的处置词时 P0 降为 P1 并提示，请人工确认（后续词同样要过语境检查，“避免违规”“此前已有单位整改”“其他单位也违规”不算）；同分句里的处置词必须针对被命中的做法；SOE-008（无出处的“行业领先”）的出处豁免沿用旧行为，是整句范围（“该技术国内领先，经省科技厅鉴定。”不报），与医院包 HOS-003 的口径不一致。
   - **表格实名规则**。带姓名列的 Markdown 表格共用全文姓名表，在所有文书类型中登记并遮蔽。有处分、安置或拟任等敏感列时，相关姓名规则在适用文书内报 P0，其余姓名列报 P1。`SOE-022` 适用所有类型，`SOE-023` 在议题材料、纪要、议案中报出。公开署名列跳过。整改分工表另有个人处分等独立敏感列时，责任人照常报出。应检查的姓名格含未识别残段时，即使同格已有姓名，该行也报一条 P1“姓名列内容未能识别，请人工核对”。括号内外均检查。姓名中间的嵌套 Markdown 和 HTML 标记按可见文字识别。相邻元素拼接后无法识别、各元素单看均为姓名时，逐人报出。两个字以上的汉字残段整段遮蔽，段内每一处以表内姓氏开头的两、三字片段也登记，长名优先。单位、部门或职务用语可能随之被遮蔽。若摘录从两个等长且重叠的片段中间开始，左侧片段可能先匹配，使右侧姓名留下尾字。少见姓氏未入姓氏表时，夹在修饰语中的姓名在别处仍可能露出。
   - **姓名列的 HTML 混排**。姓名列里，HTML 标签包住的姓名若紧邻纯文本姓名、性别或科室等徽章，即使同行有敏感列，也可能只报一条兜底 P1，漏掉逐人的 P0。评审样例中的姓名均已登记，文件名和正文摘录都已遮蔽。
   - **姓名中的 HTML 实体和注释**。二字姓名中间夹有 `&nbsp;` 或 HTML 注释时，系统可能把姓名拆成两个单字而漏登记，文件名和正文摘录可能露出原名。送检前将姓名列转为纯文本，去掉 HTML 标签、实体和注释，保留完整姓名，多人用顿号分隔。
   - **已知局限**。进入处分、名单或姓名列的单位简称也登记、遮蔽。严格定义的简称报 P1“文内已定义为单位简称，如确指单位可忽略”；只有末字提示单位嫌疑时报 P1“可能是单位简称，请人工确认”。本次出现有前置职务、个人称呼、身份括注、自然人列或个人专属处分时，沿用规则或表格级别。正文名单和无敏感列普通表仍为 P1。“对唐钢给予警告处分”报 P1，“对唐钢给予记过处分”报 P0，两者均遮蔽。单独约谈、罚款、责令整改、问责、追责、通报批评或泛指处分，不触发这条处分框架。处分框架按整词排除“安委会”“班子”“党总支”“全委会”“支委会”等集体称谓。“撤销王建国同志原任党内职务”按姓名“王建国”报 P0 并遮蔽；“撤销原任党内职务”没有处分对象姓名，不报。严格定义之外不推断单位。处分对象与处分动作隔着分句的写法可能漏报（如“李建华……已被开除党籍”）。名字里带黑名单字或地名尾字的姓名（“李山”“王会”）、与排除词同形且缺少强证据的姓名（“刘海”“林海”）、少见姓和歧义姓的弱语境会漏报。名单并列链里只要有一项被识别，其余形态合格的姓名项也登记遮蔽。无姓名类表头、缺 Markdown 分隔行或非 Markdown 表格的姓名仍可能漏报。带“·”的姓名、外文名、昵称识别不了。姓名与普通词同形时，整串替换可能把“高明的做法”里的普通词也遮掉。**文件名**按全文姓名表遮蔽。姓名只写在文件名里时，送检前需先改名。程序倒置只认固定搭配，“是否同一事项”只按字面判断，被动句、跨段、跨三句以上的写法识别不了。

## 与其他 skill 的分工

国企的通用文书（通知、总结、讲话等）由核心 skill 写，核心 skill 读同一份单位画像。

| 需求 | 用哪个 |
|---|---|
| 年度工作会报告、职代会报告、年终总结、述职述廉 | gongwen-report |
| 向国资委或上级企业的请示报告、函、通知、呈领导审批的签报 | gongwen-draft |
| 董事长、总经理讲话，主持词 | gongwen-speech |
| 党委会纪要、职代会纪要、会议记录 | gongwen-minutes |
| 民主生活会、组织生活会、党建工作报告、党课 | gongwen-party |
| 新闻稿、公众号推文、政务信息 | gongwen-brief |
| 巡视巡察、审计整改材料 | gongwen-rectify |
| 把上级通知拆成任务分解表、写贯彻落实方案 | gongwen-implement |
| 报表合并、指标计算、出图 | gongwen-data |
| 送签前全面核稿；排成 Word | gongwen-review；gongwen-format |
| 提交医院、学校、乡镇街道自身会议（含学校国资委会议）审议的议题，包括所属企业事项报这些会议审批的 | 医院交 gongwen-hospital（没装的用 gongwen-minutes）；高校、中小学、乡镇街道的议题用 gongwen-minutes，其评估、发文判断等专用文书交 gongwen-university、gongwen-k12、gongwen-grassroots |

归属看材料提交给哪个会议：提交公司党委、董事会、总经理办公会、职代会的仍用本包，出资人是学校、医院、县乡的也一样；两头都要的，公司那份用本包，学校、医院那份转交，数据保持一致（`references/profile-detail.md` 第八部分）。
